# tkim-blog

Tonghyun Kim's multilingual (ko / ja / en) tech blog.

- **Live:** https://crowdy.github.io/tkim-blog/
- **RSS:** https://crowdy.github.io/tkim-blog/rss.xml
- **Source posts (authoring):** `~/dev/crowdy/blog/`
- **Stack:** Astro 5, vanilla CSS, Pretendard, GitHub Pages, GitHub Actions

## Daily workflow

```bash
# 1. Write or edit markdown in ~/dev/crowdy/blog/
# 2. Sync into the repo (regenerates src/content/posts/)
npm run sync

# 3. Preview locally — drafts visible
npm run dev

# 4. Commit + push to deploy
git add src/content/posts
git commit -m "post: <slug>"
git push
```

A push to `main` triggers `.github/workflows/deploy.yml` → `npm ci && npm run check && npm run build` → GitHub Pages.

## Authoring conventions

- Filename `<slug>.md` for the primary language; `<slug>-ja.md` for the Japanese pair.
- Body **must** start with `# Title` — that line becomes both the frontmatter `title` and the rendered post title (the duplicate H1 inside the body is hidden via CSS).
- An optional `> blockquote` immediately after the title is captured as the post `description` (used in lang-index cards, post `<meta name="description">`, and RSS).
- Place drafts under `~/dev/crowdy/blog/draft/`. They render in `npm run dev` but are filtered out of the production build (and the RSS feed).
- Pairs of translations share the same base slug. The `LangToggle` on a post finds and links its siblings.

### Frontmatter shape (auto-generated by sync)

```yaml
---
title: '...'           # first H1
description: '...'     # > blockquote, or first paragraph (200-char cutoff)
pubDate: 2026-04-29T...Z   # file mtime
lang: ko               # ko | ja | en
pairSlug: my-post      # filename minus -ja suffix
draft: false           # true iff source is under draft/
sourceDir: root        # root | posted | draft (debug)
---
```

The schema is enforced by `src/content/config.ts`. Bad frontmatter fails the build.

## Language detection (when no `-ja` suffix)

- Hangul ratio ≥ 30% → `ko`
- Kana ratio ≥ 30% → `ja`
- Otherwise → `en`

Code fences and inline code are stripped before counting so a Korean post with heavy code blocks still classifies as `ko`.

## Commands

```bash
npm run dev        # Astro dev server
npm run sync       # ~/dev/crowdy/blog/ → src/content/posts/
npm run check      # astro check (TypeScript + content schema)
npm run build      # production build → dist/
npm run preview    # serve dist/
npm test           # vitest unit + integration
```

Override the source directory:

```bash
CROWDY_BLOG_SOURCE=/some/path npm run sync
```

## Theming

Two color modes (light / dark) driven by:

1. `localStorage.theme` if set (toggle button in header writes here)
2. otherwise `prefers-color-scheme`

Code blocks use Shiki dual theme (`github-light` / `github-dark`) and switch via the same logic.

## RSS

`src/pages/rss.xml.ts` emits all non-draft posts across all languages, newest first. Each item title is prefixed with the language code (`[ko]`, `[ja]`, `[en]`).

## Notes

- The sync script wipes `src/content/posts/` before regenerating, so do not hand-edit files there. Author in `~/dev/crowdy/blog/` and run `npm run sync`.
- CI does **not** run sync — it builds from whatever is committed under `src/content/posts/`. Keeping the source tree off the runner is intentional.
- See `docs/superpowers/specs/` for the design history (initial blog spec, AstroPaper port, nesbitt-style upgrade).
