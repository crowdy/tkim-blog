# Microsoft 가 Claude Code 를 끊은 진짜 이유 — '발로 투표' 와 '12개월 예산 몇 달 소진' 의 단위경제학

> 2026-05-22, The Verge 의 단일 보도가 그 주의 AI 업계 화제로 떠올랐다. Microsoft 가 사내 파일럿으로 운영해 온 Claude Code 라이선스를 6월 30일자로 모두 종료하고, 직원들을 GitHub Copilot CLI 로 이관한다는 내용이다. 표면의 이유는 자사 도구 통합이지만, HN 의 227 코멘트는 다른 두 줄기를 짚는다 — 개발자들이 발로 투표해 자사 도구 대신 경쟁사 도구를 골랐다는 사실, 그리고 그 결정이 회사의 12 개월 AI 예산을 몇 달에 소진시켰다는 단위경제학.

## 도입 — 발표의 명시적 사실과 그 뒤의 무게

2026 년 5 월 22 일, The Verge 의 보도는 단 한 줄로 정리된다. Microsoft 는 2025 년 12 월에 시작한 사내 Claude Code 파일럿 프로그램의 모든 라이선스를 2026 년 6 월 30 일자로 종료하고, 영향 받는 직원들 (보도에 따르면 수천 명 단위) 을 자사의 GitHub Copilot CLI 로 이관한다. 보도의 부제목에는 "MS, 자사 Notepad 에서도 Claude 를 빼고 Copilot 으로 통합" 이라는 더 작은 사실이 추가되어 있다. 발표 자체는 자사 도구 정렬 (alignment) 의 자연스러운 결과처럼 읽힌다. 그러나 HN 에 올라온 스레드는 5 시간 만에 282 점과 227 개의 코멘트를 모았고, 코멘트의 무게는 발표의 표면보다 깊은 곳을 향한다.

HN 의 가장 많은 공감을 받은 코멘트가 정확한 무대 설정을 한다 — 공감의 정서를 그대로 옮기면 — "파일럿은 비교 피드백을 모으기 위한 것이었지만, 직원들이 발로 투표해 자사 제품 대신 경쟁사 제품을 압도적으로 선택해 버렸다". 이어지는 또 다른 고공감 코멘트는 "Microsoft 의 파일럿이 2026 년 회사 AI 예산을 몇 달에 다 써 버렸다 (accidentally consumed their 2026 yearly target spend on AI)" 라는 더 충격적인 사실을 짚는다. 두 사실이 합쳐지면 발표의 진짜 의미가 드러난다. 도구의 채택은 직원의 선호로는 명확히 결판이 났고, 같은 결판이 회사의 단위경제학으로는 견딜 수 없는 청구서가 됐다.

본 글은 이 사건의 진짜 두 축 — '발로 투표' 의 의미와 '12 개월 예산 몇 달 소진' 의 단위경제학 — 을 분리해 분석하고, 토큰의 시대에 기업이 AI 코딩 도구를 평가하는 기준이 어떻게 바뀌고 있는가를 짚는다.

## 본문 1 — '발로 투표' 의 단순함과 그 비대칭

먼저 첫 번째 사실. 파일럿의 결과는 명확했다. 비교 사용 환경 — 같은 개발자들이 Claude Code 와 GitHub Copilot 을 둘 다 쓸 수 있는 환경 — 에서 사용 시간, 호출 수, 만족도 응답 모두 Claude Code 가 압도했다. HN 의 코멘트 가운데 Microsoft 내부 사정에 친숙한 익명 코멘터가 짚는 한 줄 — 공감 코멘트의 정서 요약 — 은 이렇다. "리더십이 기대한 것과 정반대 결과가 나왔다, 직원들은 자사 제품을 의무감으로 쓰는 사람들이 아니다".

이 결과의 단순함이 사건의 첫 번째 무게다. 보통의 사내 파일럿은 "둘 다 비슷한데, 우리 것이 통합 측면에서 약간 더 낫다" 같은 모호한 결론으로 정리된다. 이번 파일럿은 그러지 못했다. 개발자의 행동은 모호하지 않았고, 그 행동이 만든 데이터는 도구의 우위를 부정할 여지가 없었다. 단지 우위를 확인했다는 사실 자체가 문제다 — 사내 비교의 결과가 곧 사내 도구의 패배라는 명백한 메시지가 됐기 때문이다.

여기서 두 번째 무게가 따라온다. 도구의 우위가 명백하게 드러나도, **그 우위가 회사의 단위경제학 안에서 지속 가능하지 않으면** 그 우위는 채택 결정의 단일 기준이 되지 않는다. The Verge 의 보도와 HN 의 코멘트가 합쳐 그려내는 그림이 정확히 그것이다. 발로 투표는 한 변수, 단위경제학은 다른 변수. 두 변수가 같은 방향을 가리키지 않으면, 기업 의사결정은 후자를 더 크게 본다.

이 비대칭의 가장 날카로운 표현을 HN 의 한 코멘트가 던진다 — "tokens are current era's lines of code per month" (토큰이 현 시대의 월간 코드 줄 수다). 한 줄로 무엇을 말하는가. 과거 20 년 동안 소프트웨어 도구의 단위경제학은 좌석 수 (seats), 호출 수 (calls), 처리량 (throughput) 같은 측정 가능한 자원으로 정의됐다. 클라우드 시대에는 CPU 시간, 메모리, 네트워크 바이트가 단위가 됐다. 2026 년의 AI 코딩 도구 시대에는 토큰이 그 단위다. 그리고 토큰의 단위경제학은 앞선 단위들과 두 가지 측면에서 본질적으로 다르다.

첫째, 토큰 소비는 사용자의 작업 양이 아니라 **에이전트의 추론 깊이** 와 더 크게 결합된다. 같은 코드 변경 작업을 시키더라도, Claude Code 가 더 많은 컨텍스트를 읽고, 더 많은 도구 호출을 하고, 더 긴 추론을 진행하면 토큰 소비는 5 ~ 10 배까지 커진다. 사용자는 같은 일을 했지만 청구서는 다섯 배다. 둘째, 토큰 소비는 **회사가 통제할 수 없는 외부 가격 변수** 에 묶여 있다. Anthropic 이 모델 가격을 조정하면 회사의 청구서가 즉시 영향을 받는다. AWS / Azure / GCP 의 컴퓨트 시간 가격이 안정적인 것과 정반대다.

이 두 성질이 합쳐지면, AI 코딩 도구의 단위경제학은 좌석 수 기반 SaaS 의 단위경제학과 본질적으로 다른 종류가 된다. 좌석 라이선스 모델에서는 1 인당 월 \$30 이 1 만 명이면 월 \$30 만, 연 \$3.6M 이다. 이 숫자는 1 년 단위로 예측 가능하고 예산화 가능하다. 토큰 모델에서는 1 만 명의 사용 강도가 5 ~ 10 배의 범위를 가지고, 그 범위가 같은 분기 안에 변동한다. 예산화의 기본 가정 — "수요는 좌석 수에 비례한다" — 이 무너진다.

Microsoft 의 12 개월 AI 예산이 몇 달에 소진된 이유가 정확히 이 단위경제학의 성질이다. 좌석 수 기반의 예산화로 잡혀 있던 숫자가, 토큰 기반의 실제 사용에서는 5 배 이상으로 폭주했다. 그리고 그 폭주가 의도된 것이 아니라 — 개발자의 자연스러운 사용에서 — 발생했다는 점이 가장 무겁다. 단순히 "Claude Code 가 비쌌다" 가 아니라, "Claude Code 의 자연스러운 사용 강도가 예산화 가정을 넘는다" 가 정확한 진단이다.

## 본문 2 — 토큰 경제의 새 변수와 도구 평가의 재편

이 사건이 더 큰 시대정신과 만나는 지점이 여기다. 좌석 수에서 토큰으로 단위경제학이 옮겨가는 흐름은 Microsoft 만의 문제가 아니다. 모든 대기업의 CFO 가 같은 문제 앞에 있다. 그리고 그 문제의 핵심은 도구 평가의 기준 자체가 다층화된다는 것이다.

전통적 SaaS 평가에서는 두 변수가 결정한다 — 좌석당 가격과 사용자 만족도. 두 변수가 정해지면 ROI 계산이 단순하다. AI 코딩 도구의 평가에는 적어도 다섯 변수가 들어온다. 첫째, 좌석당 라이선스 비용 (이 부분은 종종 0 에 가깝거나 정액제). 둘째, 토큰 사용량의 분포 (median, p95, p99). 셋째, 토큰 사용의 시간적 변동 (peak hour, peak week). 넷째, 모델 가격의 외부 변동 위험. 다섯째, 도구가 만들어 내는 개발자 생산성의 측정값. 다섯 변수 가운데 어느 하나가 큰 범위로 변동하면 ROI 계산 전체가 흔들린다.

Microsoft 의 결정은 다섯 번째 변수 (생산성 우위) 가 분명함에도, 둘째 / 셋째 / 넷째 변수의 변동성을 통제할 수 없다는 판단에서 나온 것으로 읽힌다. HN 의 한 코멘트가 정확히 짚는다 — 공감의 정서를 그대로 옮기면 — "Microsoft 는 두 선택지를 마주했다. 분명히 우월한 도구의 상당한 지속 비용을 계속 지불할 것인가, 자사 플랫폼으로 통합해 비용 통제와 전략적 정렬을 얻을 것인가". 6 월 30 일은 그 두 선택의 균열 시점이다.

여기서 또 하나의 미묘한 변수가 등장한다. **GitHub Copilot CLI 는 Claude 모델에 접근할 수 있다**. HN 의 여러 코멘트가 이 사실을 강조한다. 즉 Microsoft 의 결정은 "Claude 를 끊는다" 가 아니라 "Claude 를 자사 진입점 (Copilot CLI) 을 통해서만 쓰게 한다" 다. 차이는 무엇인가. 진입점 통제의 의미가 두 가지다. 첫째, Claude 호출의 사용 패턴 — 어떤 컨텍스트, 어떤 도구, 어떤 토큰 크기 — 을 Microsoft 가 게이트하고 측정할 수 있다. 둘째, Microsoft 가 그 호출을 자사 인프라 (Azure 와 Microsoft AI 의 통합 계층) 를 거치게 하면, 다른 모델 (자사 모델, 다른 외부 모델) 로 가격 비교에 따라 라우팅할 수 있는 선택지가 열린다. 즉 진입점 통제는 토큰 단위경제학의 가장 큰 위험 (외부 가격 변동) 을 부분적으로 헤지하는 장치다.

이 헤징의 비용은 사용자 경험의 일부 손실이다. Claude Code 의 사용자 경험은 단순히 모델 성능이 아니라, 모델 + UI + 도구 통합 + 컨텍스트 관리의 결합으로 만들어진다. Copilot CLI 가 Claude 모델을 호출하더라도, 그 결합은 Claude Code 의 결합과 다르다. 개발자가 발로 투표한 것은 모델만이 아니라 그 결합이었다. Microsoft 의 결정은 결합의 일부 (모델) 는 유지하고, 결합의 다른 일부 (UI / 통합) 는 자사 도구로 대체한다. 6 월 30 일 이후 직원들의 사용 만족도가 어떻게 움직이는지가 이 결정의 두 번째 검증 지표가 된다.

또 한 가지 미묘한 비대칭이 있다. Microsoft 와 Anthropic 의 관계는 OpenAI 와 다르다. OpenAI 와의 협력은 자본 (Microsoft 의 OpenAI 투자) 과 인프라 (Azure 위의 OpenAI 서빙) 가 깊이 묶여 있는 구조다. Anthropic 과의 관계는 그보다 가볍다 — 일부 Anthropic 모델이 Azure 에서 서빙되지만, 자본 결합은 미미하다. HN 의 한 코멘트가 이 비대칭을 짚는다 — 공감 코멘트의 정서 요약 — "Microsoft 는 OpenAI 와 공개적으로 갈등했고, 그 갈등 위에서 Anthropic 과의 가까운 채택은 정치적으로 어려운 카드다". Claude Code 의 사내 채택을 끊는다는 것은, OpenAI 와의 미묘한 관계 위에서 Anthropic 의존도가 빠르게 커지는 것을 저지하는 정치적 행동이기도 하다. 단위경제학의 결정에 정치학의 결정이 얹혀 있다.

## 본문 3 — 코퍼레이트 도구 채택의 새 시대

이 사건이 다음 6 ~ 12 개월에 코퍼레이트 도구 채택의 패턴에 만들 영향을 짚어 보자. 세 갈래로 정리된다.

첫째, **'토큰 예산화' 의 표준화**. Microsoft 가 12 개월 AI 예산을 몇 달에 소진한 사건은 모든 대기업의 CFO 에게 직접 가르침이다. 좌석 수 기반의 예산화로는 토큰 사용을 통제할 수 없다는 사실이 가시화됐다. 6 ~ 12 개월 안에 대기업의 AI 도구 채택 프로세스에 "토큰 한도 (token budget) 설정" 이라는 새 단계가 표준이 될 것이다. 좌석당 일일 / 주간 / 월간 토큰 상한이 정해지고, 그 상한을 초과하면 자동 차단되거나 비용을 부서가 부담하는 구조다. 이는 클라우드 시대의 "비용 알람 (cost alert)" 과 비슷한 형상이지만, 더 깊은 부분에서 도구의 사용 패턴 자체를 형성한다.

둘째, **'API 게이트웨이' 가 진입점이 되는 패턴의 가속**. 단일 도구의 단일 진입점을 직접 직원에게 주는 모델 (Claude Code 의 직접 라이선스) 은 사용 패턴을 통제할 수 없다. 그 대신 회사가 자체 게이트웨이를 운영하고, 게이트웨이가 외부 모델 (Anthropic, OpenAI, 또는 자사 모델) 로 호출을 라우팅하는 모델이 표준이 된다. Microsoft 의 GitHub Copilot CLI 는 이 패턴의 대표 사례다. 비슷한 게이트웨이 도구가 다른 대기업 (Google 의 Workspace AI, Amazon 의 Q Developer, Salesforce 의 Agentforce) 에서도 빠르게 확장된다. 이 확장의 결과는 외부 AI 모델 회사 (Anthropic, OpenAI) 의 직접 사용자 (B2C 식 직접 라이선스) 가 줄어드는 것이다. 모델 회사들은 자기 모델이 잘 팔리는 것을 보면서도, 게이트웨이 뒤에 가려져 있는 사용 패턴을 직접 볼 수 없게 된다.

셋째, **'우월한 도구의 거부' 라는 의사결정의 정상화**. 5 ~ 10 년 전 SaaS 시대에는 "직원이 가장 좋아하는 도구를 사주는 것" 이 인재 유지의 일부였다. 토큰 시대에는 그 등식이 깨진다. 가장 좋아하는 도구가 회사의 단위경제학 안에서 지속 가능하지 않을 수 있다. Microsoft 의 결정은 "직원의 선호 > 도구 성능 > 단위경제학" 의 전통적 우선순위를 "단위경제학 > 도구 성능 > 직원의 선호" 로 뒤집는 신호다. 이 뒤집기가 다른 대기업에서도 같은 방향으로 일어나면, AI 코딩 도구 시장의 경쟁 구도는 "도구의 성능" 만으로는 결판이 나지 않는다. "회사의 단위경제학 안에서 비용이 예측 가능한가" 라는 두 번째 변수가 동등하게 중요해진다.

이 세 갈래가 모두 일어나면, Claude Code 같은 도구의 미래 시장 전략이 본질적으로 바뀐다. B2C 식 직접 라이선스로는 대기업 시장에 도달하기 어려워지고, 게이트웨이 뒤에 라우팅되는 모델 공급자가 되어야 한다. Anthropic 의 다음 1 년의 시장 전략 — 직접 도구 (Claude Code) 인가, API 모델 (Claude API) 인가 — 이 이 사건으로 인해 직접 도구 쪽 비중이 줄어들 가능성이 있다. 직접 도구의 매력은 사용자 경험의 결합이지만, 그 결합이 게이트웨이 뒤에서 부분적으로 풀어지면 직접 도구의 차별성이 약해진다.

여기서 한 가지 반론을 다뤄야 한다. Microsoft 의 사례가 모든 대기업에 일반화 가능한가. 한 가지 이유로 일반화에 한계가 있다. **Microsoft 는 자사가 경쟁 도구 (GitHub Copilot) 를 가지고 있다**. 자사 도구가 없는 대기업 — 금융, 제조, 헬스케어의 다수 — 은 외부 도구를 끊는 것이 자동으로 자사 도구로의 이관이 되지 않는다. 외부 도구의 단위경제학 문제는 그들에게도 같지만, 그 대응은 "끊고 자사로 이관" 이 아니라 "한도 설정 후 계속 사용" 이 된다. 즉 Microsoft 의 사례는 자사 경쟁 도구가 있는 소수 대기업의 특수한 결정이고, 단위경제학의 문제 자체는 모든 대기업이 직면하지만 그 해법은 두 갈래 — 한도 설정 vs 자사 이관 — 로 나뉜다.

## 결론 — 토큰의 시대에 도구는 어떻게 평가되는가

처음의 질문으로 돌아가자. Microsoft 가 Claude Code 를 끊은 진짜 이유는 무엇인가.

표면의 이유는 자사 도구 (GitHub Copilot CLI) 로의 통합이었다. 그러나 진짜 이유는 두 갈래로 분리된다. 첫째, 사내 비교 파일럿이 자사 도구의 명확한 패배를 가시화했기에, 그 결과를 공식 결론으로 받아들이는 것이 정치적으로 어려워졌다. 둘째, 더 결정적으로, Claude Code 의 자연스러운 사용 강도가 회사의 12 개월 AI 예산을 몇 달에 소진시킬 만큼 컸기에, 좌석 수 기반의 예산화로는 통제 불가능한 단위경제학이 됐다. 두 이유는 어느 한쪽만으로는 단절 결정을 정당화하기 어렵지만, 합쳐지면 6 월 30 일의 단절이 회사의 합리적 선택으로 정리된다.

이 사건이 남기는 한 줄의 메시지는 이렇다. **토큰의 시대에 AI 도구의 평가는 성능과 단위경제학의 곱으로 정의되고, 두 변수가 같은 방향을 가리키지 않으면 단위경제학이 더 큰 무게를 가진다.** 좌석 수 기반의 SaaS 평가 시대는 끝났고, 토큰 기반의 사용 강도 평가 시대가 시작됐다. 그리고 이 새 시대의 도구 채택 결정은 직원의 선호만으로 결판나지 않는다. 회사의 CFO 와 개발자의 선호가 같은 방향을 가리키지 않을 때, 결정은 CFO 의 방향으로 기운다.

다음 6 ~ 12 개월에 검증될 세 가지 지표가 있다. 첫째, 다른 대기업 가운데 같은 식의 단절 (외부 AI 코딩 도구 끊고 사내 게이트웨이로 이관) 이 일어나는지. 둘째, Anthropic 의 매출 구조 가운데 직접 도구 (Claude Code) 의 비중이 감소하고 API 모델의 비중이 증가하는지. 셋째, "토큰 예산" 이라는 표현이 대기업의 분기 보고서에 등장하기 시작하는지. 세 가지 가운데 둘 이상이 긍정적으로 나오면, 2026-05-22 의 The Verge 보도는 토큰 시대의 첫 번째 거시적 분기점으로 기록될 것이다.
