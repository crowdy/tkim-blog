# 에이전틱 비디오 프로덕션의 시작: OpenMontage가 12개 파이프라인으로 여는 것

> AI 코딩 어시스턴트가 코드를 넘어 영상까지 만들어야 한다면, 그 경계선은 어디에 그어지는가?

## 도입

2026년 현재, AI 비디오 생성 도구는 과잉 공급의 시대에 접어들었다. Sora, Runway, Kling, Hailuo 등 텍스트-투-비디오 모델은 수십 개에 달하고, 영상 편집을 보조하는 AI 플러그인 역시 기존 NLE(Non-Linear Editor) 생태계 전반에 스며들었다. 그럼에도 불구하고 실제 프로덕션 현장에서 느끼는 고통은 사라지지 않았다. 생성 모델이 '클립'을 만들어 줄 수는 있어도, 연구에서 출발해 스크립트를 쓰고, 에셋을 수급하고, 편집하고, 최종 파일로 합성하기까지의 전체 워크플로는 여전히 인간 편집자가 접착제 역할을 맡아야 한다.

OpenMontage는 이 접착제 문제를 정면으로 겨냥한다. GitHub Trending에서 일주일 만에 1만 5,793개의 별을 모은 이 프로젝트는 스스로를 "에이전틱 비디오 프로덕션 시스템"으로 정의한다. 핵심 주장은 명확하다. Claude Code, Cursor, GitHub Copilot처럼 이미 개발자 워크플로에 자리잡은 AI 코딩 어시스턴트를 그대로 활용해 완전한 비디오 프로덕션 스튜디오로 전환할 수 있다는 것이다.

단순한 래퍼(wrapper) 도구가 아니다. 52개의 실행 가능한 Python 도구, YAML로 작성된 파이프라인 매니페스트, Markdown 형식의 에이전트 스킬 파일이 3레이어 구조를 이루고 있으며, 12개의 전문화된 프로덕션 파이프라인이 각자 다른 콘텐츠 유형을 담당한다. 제로 비용 경로(Zero-cost path)를 통해 유료 API 없이도 완성된 영상을 뽑아낼 수 있다는 주장도 함께 따라온다.

이 글은 OpenMontage의 아키텍처와 차별점을 기술적으로 분석하고, 에이전틱 크리에이티브 도구가 콘텐츠 생산의 트레이드오프를 어떻게 재편하는지를 살펴본다.

## 세 겹의 구조: 도구, 파이프라인, 스킬이 만드는 레이어드 아키텍처

OpenMontage의 아키텍처를 이해하는 데 가장 좋은 출발점은 세 개의 레이어가 서로 어떤 역할을 분담하는지를 파악하는 것이다.

**첫 번째 레이어: Python 도구 (tools/)**

52개의 Python 실행 파일로 구성된 이 레이어는 실제 작업을 수행하는 최하단 계층이다. 각 도구는 단일 책임 원칙을 따른다. 예컨대 `fetch_footage.py`는 Archive.org, NASA 아카이브, Pexels, Wikimedia Commons에서 무료 영상 소스를 가져오는 역할만 한다. `clip_semantic_search.py`는 CLIP 임베딩을 이용해 텍스트 쿼리에 가장 근접한 영상 클립을 찾는다. `tts_piper.py`는 로컬에서 실행되는 Piper TTS 엔진을 호출해 음성을 합성한다. `ffmpeg_compose.py`는 FFmpeg 래퍼로 최종 합성을 담당한다.

도구들은 JSON 형식의 표준 입출력 인터페이스를 통해 에이전트와 통신하도록 설계되어 있다. AI 코딩 어시스턴트가 MCP(Model Context Protocol)나 Tool Use API를 통해 직접 호출할 수 있는 구조다. 중요한 것은 각 도구가 독립적으로 실행 가능하다는 점이다. 에이전트가 없어도 CLI에서 직접 테스트할 수 있어 디버깅이 용이하다.

**두 번째 레이어: YAML 파이프라인 매니페스트 (pipelines/)**

12개의 파이프라인이 각각 YAML 파일로 정의된다. Animated Explainer, Animation, Avatar Spokesperson, Cinematic, Clip Factory, Documentary Montage, Hybrid, Localization & Dub, Podcast Repurpose, Screen Demo, Talking Head가 포함된다. 각 YAML 매니페스트는 파이프라인의 실행 단계(stages), 각 단계에서 호출할 도구(tools), 단계 간 데이터 흐름(data flow), 체크포인트 설정, 예산 임계값을 선언적으로 기술한다.

이 설계의 핵심은 선언적 구성과 실행 가능한 코드의 분리다. 파이프라인 매니페스트는 "무엇을 할지"를 정의하고, Python 도구는 "어떻게 할지"를 구현한다. 에이전트는 이 둘을 연결하는 실행자 역할을 한다. 새로운 파이프라인을 추가하거나 기존 파이프라인을 수정할 때 Python 코드를 건드리지 않아도 된다는 장점이 있다.

**세 번째 레이어: Markdown 스킬 파일 (skills/)**

가장 흥미로운 레이어다. 에이전트가 프로덕션 결정을 내릴 때 참조하는 맥락 문서를 Markdown으로 작성해 두었다. 각 스킬 파일은 프로덕션 규칙, 공급자 선택 기준, 품질 판단 기준을 자연어로 기술한다. Claude Code나 Cursor 같은 AI 에이전트는 컨텍스트 창에 해당 스킬 파일을 로드한 상태에서 작업을 수행한다.

이 접근법은 "에이전트를 훈련시키는 것"이 아니라 "에이전트에게 전문 지식 문서를 제공하는 것"에 가깝다. 스킬 파일의 내용이 잘못되거나 불완전하면 에이전트의 판단도 그 수준을 벗어나지 못한다. 반대로 스킬 파일을 정교하게 작성할수록 에이전트의 프로덕션 판단이 정밀해진다.

**공급자 선택 시스템**

OpenMontage는 7차원 스코어링 시스템으로 14개의 비디오 생성 공급자, 10개의 이미지 도구, 4개의 TTS 서비스를 순위 매긴다. 7개 차원은 품질, 속도, 비용, 신뢰성, API 접근성, 라이선스 조건, 스타일 일관성이다. 각 파이프라인은 자신의 요구사항 프로필에 따라 최적 공급자를 자동 선택한다. 저비용 프로토타입 단계에서는 낮은 비용과 속도에 가중치를 두고, 최종 납품 단계에서는 품질과 라이선스 조건을 우선시하는 방식이다.

## 차별점의 실체: 제로비용 경로, CLIP 기반 Documentary Montage, 프로덕션 거버넌스

OpenMontage를 단순한 비디오 자동화 스크립트 묶음과 구분짓는 것은 세 가지 요소다.

**제로비용 경로의 실현 가능성**

OpenMontage가 내세우는 "유료 API 없이 완성된 영상 제작"은 구체적인 도구 스택으로 뒷받침된다. 음성 합성은 Piper TTS(로컬 실행, 완전 무료)로 처리하고, 편집 및 합성은 FFmpeg로 수행한다. 리액트 기반 합성 엔진 Remotion은 오픈소스 라이선스 하에 사용 가능하다. 동영상 소스는 Archive.org의 인터넷 아카이브, NASA 공개 영상 라이브러리, Pexels 무료 플랜, Wikimedia Commons에서 조달한다.

물론 이 제로비용 경로에는 한계가 있다. Piper TTS의 음성 품질은 상업용 TTS와 격차가 있고, 무료 영상 소스는 소재의 다양성과 품질에서 제한적이다. 그러나 프로토타입 제작, 사내 교육 자료, 저예산 콘텐츠 제작 맥락에서는 충분히 실용적인 경로다. 기존에는 이런 수준의 자동화조차 상당한 스크립팅 작업을 요구했다.

**Documentary Montage 파이프라인과 CLIP 시맨틱 검색**

12개 파이프라인 중 가장 기술적으로 흥미로운 것은 Documentary Montage다. 이 파이프라인은 텍스트 쿼리를 기반으로 공개 영상 아카이브에서 관련 클립을 자동으로 탐색하고, 내레이션 스크립트에 맞춰 시퀀스를 구성한다.

핵심 기술은 CLIP(Contrastive Language-Image Pre-training) 임베딩을 이용한 시맨틱 검색이다. 기존의 태그 기반 검색이 "war footage"나 "space exploration"처럼 명시적 키워드에 의존하는 것과 달리, CLIP 기반 검색은 "1960년대 냉전 시대의 불안감을 담은 도시 풍경"같은 추상적 쿼리도 처리할 수 있다. 스크립트의 각 단락이 내포하는 시각적 의미를 파악해 가장 적합한 클립을 매핑하는 방식이다.

이 파이프라인이 완성되면, 리서처가 주제를 입력하면 에이전트가 리서치를 수행하고, 스크립트를 작성하고, 관련 공개 영상을 수집해 내레이션과 함께 편집된 다큐멘터리를 출력하는 단일 워크플로가 구현된다. 인간 편집자가 전통적으로 수행하던 "B-roll 선택"과 "타이밍 매칭" 작업을 에이전트가 담당하게 되는 것이다.

**프로덕션 거버넌스: 검증, 자기 검토, 슬라이드쇼 리스크 스코어링**

에이전틱 시스템에서 자주 간과되는 문제는 결과물의 품질 통제다. OpenMontage는 이를 위해 세 가지 거버넌스 메커니즘을 내장한다.

첫째, 사전 합성 검증(pre-compose validation)이다. 에셋이 모두 수집된 뒤 실제 합성 전에 에이전트가 전체 씬 플랜을 검토하고 잠재적 문제를 식별한다. 오디오-비디오 길이 불일치, 라이선스 충돌, 해상도 혼용 같은 기계적 문제를 사전에 잡아낸다.

둘째, 사후 렌더 자기 검토(post-render self-review)다. 최종 렌더링이 완료된 뒤 에이전트가 출력 파일을 다시 분석해 품질 기준을 충족했는지 평가한다. 이 단계에서 기준 미달 판정이 내려지면 특정 단계를 재실행하거나 대안 에셋으로 교체하는 루프가 발동된다.

셋째, 슬라이드쇼 리스크 스코어링이다. 이 개념이 특히 눈에 띈다. "슬라이드쇼 리스크"는 영상이 실질적인 동영상이 아니라 정지 이미지의 연속처럼 느껴질 위험을 6개 차원으로 정량화한다. 모션 다양성, 편집 리듬, 씬 전환 패턴, 동적 요소 비율 등이 포함된다. 이 스코어가 임계값을 초과하면 에이전트가 더 많은 동적 클립을 수급하거나 전환 효과를 추가하는 조치를 취한다.

예산 통제도 거버넌스의 일부다. 기본값은 \$10 총 지출 한도이며, 액션 단위로 승인 임계값을 설정할 수 있다. 외부 API를 호출하는 각 도구는 예상 비용을 사전에 에이전트에게 보고하고, 임계값 초과 시 인간 승인을 요청하는 방식이다.

**체크포인팅과 결정 로그**

아키텍처 결정 중 프로덕션 신뢰성에 가장 크게 기여하는 것은 체크포인팅과 결정 로그다. 에이전틱 워크플로는 실행 중 실패할 수 있다. 네트워크 오류, API 타임아웃, 도구 버그 등 실패 원인은 다양하다. OpenMontage는 각 단계 완료 시 상태를 체크포인트로 저장한다. 이는 실패 후 처음부터 재시작하는 대신 마지막 성공 단계부터 재개할 수 있게 해준다.

결정 로그는 에이전트가 각 단계에서 내린 선택과 그 근거를 기록한다. 어떤 공급자를 선택했는지, 어떤 클립을 왜 선택했는지, 예산 결정이 어떻게 이루어졌는지를 추적할 수 있다. 이는 디버깅과 품질 개선 루프에서 핵심 데이터 소스로 기능한다.

## 에이전틱 크리에이티브 도구의 시사점과 트레이드오프

OpenMontage의 등장은 단순히 "비디오 생성 도구가 하나 더 나왔다"는 수준을 넘어서는 함의를 가진다. 이는 에이전틱 AI 시스템이 크리에이티브 프로덕션 영역으로 확장되는 방식을 보여주는 구조적 사례다.

**인프라로서의 크리에이티브 파이프라인**

기존의 비디오 프로덕션 자동화 시도들은 대부분 특정 작업(트랜스크립션, 자막 생성, 클립 트리밍)을 자동화하는 데 초점을 맞췄다. OpenMontage의 접근법은 다르다. 전체 프로덕션 워크플로를 인프라 코드처럼 다룬다. YAML 파이프라인 매니페스트는 CI/CD 파이프라인 설정과 구조적으로 유사하고, 체크포인팅은 분산 컴퓨팅에서 일반적인 내결함성 패턴이다.

이 관점에서 보면 OpenMontage는 "비디오 제작 소프트웨어"가 아니라 "비디오 프로덕션 인프라"다. 이 차이는 중요하다. 인프라는 버전 관리되고, 테스트되고, 배포되고, 모니터링된다. 크리에이티브 의사결정도 동일한 엔지니어링 원칙 아래 두겠다는 선언이다.

**AI 코딩 어시스턴트를 실행자로 선택한 이유**

OpenMontage가 전용 에이전트 프레임워크 대신 AI 코딩 어시스턴트를 선택한 것은 전략적 결정이다. Claude Code, Cursor, Copilot은 이미 수백만 명의 개발자가 매일 사용하는 도구다. 이 도구들에 새로운 스킬을 추가하는 방식으로 접근하면 별도의 플랫폼 학습 비용 없이 비디오 프로덕션 능력을 확장할 수 있다.

기술적으로는 MCP(Model Context Protocol)나 Tool Use API를 통해 Python 도구를 AI 어시스턴트에 연결하는 방식이 성숙해졌다. OpenMontage의 52개 Python 도구는 이 인터페이스를 통해 AI 어시스턴트가 직접 호출할 수 있도록 설계되어 있다.

**한계와 트레이드오프**

OpenMontage가 해결하지 못하는 문제도 명확하다. 창의적 판단의 주관성이 첫 번째 한계다. 슬라이드쇼 리스크 스코어링이나 사후 검토가 기계적 품질 기준을 자동화할 수 있어도, "이 영상이 감동적인가", "이 편집 리듬이 메시지를 강화하는가" 같은 판단은 여전히 인간의 영역에 속한다.

저작권과 라이선스 복잡성도 실제 배포 환경에서 문제가 된다. 제로비용 경로에서 활용하는 공개 소스 영상들의 라이선스 조건은 다양하고 복잡하다. 에이전트가 라이선스 조건을 파악해 충돌을 피한다고 주장하지만, 법적 책임의 최종 귀착점은 여전히 사용자다.

컨텍스트 창 한계도 실제 프로덕션에서 걸림돌이 된다. 장편 영상 프로젝트는 수백 개의 클립, 수천 줄의 스크립트, 복잡한 씬 그래프를 다루어야 한다. 현재 AI 어시스턴트의 컨텍스트 창으로는 이 모든 정보를 동시에 처리하기 어렵다. 체크포인팅이 일부 완화책이 되지만, 맥락 단절로 인한 일관성 문제는 남는다.

## 결론

OpenMontage는 에이전틱 AI가 "도구 사용자"에서 "프로덕션 파이프라인 실행자"로 진화하는 방향을 보여주는 프로젝트다. 3레이어 아키텍처, 12개 전문화 파이프라인, 7차원 공급자 스코어링, 내장 거버넌스 메커니즘은 단순한 자동화 스크립트를 넘어선 설계 수준을 보여준다.

무엇보다 의미 있는 것은 제로비용 경로와 Documentary Montage 파이프라인의 조합이다. 이는 고가의 상업 도구 없이도 연구에서 편집 완료 영상까지의 워크플로를 자동화할 수 있는 경로를 열어준다. 저예산 콘텐츠 크리에이터, 교육 기관, 비영리 단체에게 이 접근법은 실질적인 비용 장벽을 낮추는 효과가 있다.

그러나 OpenMontage가 "비디오 편집자를 대체한다"는 주장은 과장에 가깝다. 에이전틱 시스템이 기계적 판단과 반복 작업에서 강점을 발휘하는 반면, 크리에이티브 방향 설정과 감성적 판단은 여전히 인간의 역할로 남는다. 에이전틱 비디오 프로덕션의 진정한 가치는 인간 크리에이터가 기술적 실행에 쏟던 시간을 창의적 의사결정에 재배치할 수 있게 해주는 데 있다.

AI 코딩 어시스턴트가 코드 저장소를 관리하듯 비디오 프로덕션 파이프라인을 관리하는 세계가 열리고 있다. OpenMontage는 그 세계의 초기 지도를 그리고 있다.
