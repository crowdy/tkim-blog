# AI 要件定義 3 年の記録 — 熊井悠が見つけた 「AI が速くなるほどボトルネックは上流へ移動する」 という命題

> コードは AI で速く作れるようになったが、何を作るかの決定はその速さに追いつかない。3 年の実測が指し示す新しいボトルネックの場所はどこか。

## 導入 — 142 likes の Qiita 振り返りが生んだ合意

2026 年 6 月 14 日、日本の AI スタートアップ GEAR.indigo Biz の代表 熊井悠 が Qiita に長い振り返りを投稿した。タイトルは 「3 年間、AI 要件定義に取り組んできた全記録」 だった。分量は短くない。だが日本のエンジニアコミュニティの反応速度は速かった。24 時間で 142 likes を得て、Qiita の週間トレンド上位に上がった。同じ週のより短く軽い記事のほうが点数で上回ったこともあるが、この振り返りは別種の反応を集めた。SIer と IT サービス業界の上流工程担当者が、自分の仕事の未来について初めて自分の言葉を持てたという手応えの反応だった。

熊井の出身は日本の SIer と IT コンサルティングだ。彼が 3 年間続けてきたのは単純なことだ。要件定義 — SIer 業界の最も上流の工程 — に LLM をどこまで、どのように差し込めるかの実測である。その実測の結論を一文に整理した文章が、この振り返りの最も重い一行だ。「AI で開発が速くなるほど、ボトルネックは上流へ移動する」 。この命題が指す風景は単なる道具の振り返りを超える。何を作るかの決定そのものが新しいボトルネックになった時代に、その決定の場所がどこへ移るかを問う仕事である。

## 3 年の時系列 — 道具の進化と発見の順序

熊井の記録は時間順に七段階を踏む。各段階の核心の発見を一行ずつ拾うだけで、全体の風景が見える。

**2023.7 — 「事前情報 (用語集·前提) の整理が精度を決める」 。** 最初の段階は単純だった。会議メモを GPT-3.5 に投げてフロー図を生成する仕事である。結果はしばしば外れた。理由は明らかだった。社内用語、ビジネスドメインの略語、前回会議の結論といった事前情報がプロンプトに入っていないと、LLM は常に一般的な答えへ回帰する。最初の発見は道具の限界ではなく、道具に与えるコンテキストの限界だった。

**2023.10 — 「コードベースこそ最良のコンテキストだ」 。** 第二段階は Cursor の登場と共にやってきた。会議メモだけでなく、既存コードベース自体をコンテキストとして束ねて投げる方式へ移った。すると要件定義文書の精度が一段飛んだ。コードは単なる実装ではなく、ドメインの最も正直な形式の仕様だった。熊井の表現では 「定性的な情報でもコンテキストに含めるだけで、生成の精度は格段に変わる」 。

**2024.3 — 「ノウハウは『展開』 より 『蓄積』 から来る」 。** 社内の一部チームに ChatGPT の導入が始まった。熊井の発見は導入そのものよりその結果にあった。ある一人の良いプロンプトを他チームへ展開しようとしても成功率が低かった。実際に効果を見たチームは、自分のドメインの小さなプロンプトを時間をかけて積み重ねたチームだった。普遍的なベストプラクティスという幻想から離れ、ドメインごとの小さなコンテキストの累積というより重い仕事を引き受けた瞬間である。

**2024.9 — 「単発プロンプトから 『仕組み』 へ転換」 。** 会議室で毎回一行のプロンプトを入力する方式から離れ、会議メモ → 事前情報 → コードベース → 出力フォーマットのパイプラインを自動化する方式へ移った。Project as Code という語がこの段階で登場する。Markdown とコードでプロジェクトのすべての情報を一つのディレクトリに集め、そのディレクトリ自体を LLM の入力とする。

**2025.8 — 「骨格はコードに、要件はプロンプトに分離」 。** Cursor と Claude Code が本格導入され、システムの骨格コードは事前に敷いておき、その上に要件をプロンプトで載せる方式が定着した。熊井が 「0 日導入 (0 日で動くシステムの上で要件定義を始める)」 と呼ぶパターンである。これは紙の上の仕様から始めて 1 か月後に初動を見ていた従来のウォーターフォールサイクルを 0 日に圧縮する。

**2025.11 — 「要件定義は 『文書作成』 から 『スコープ決定』 へ移る」 。** 道具が十分に速くなった場所で、本当のボトルネックが見えた。何を作るかの決定。どこまで作ってどこで止まるかの合意。AI が文書を速く作るほど、その文書が刻む決定の重みが増した。従来の SI では要件定義書一冊が 「決定の凝縮」 だったが、AI 時代には要件定義書が速く多く出すぎて、人の決定が追いつかない。

**2026.5 — 「道具自体は無料化し、決定を阻む障壁を取り除く」 。** GEAR.indigo Biz が BYOK (Bring Your Own Key) 方式で無料化された瞬間だ。熊井の表現は明確である。「月額課金という入り口の障壁を残したまま 『民主化』 を語るのは、矛盾です」 。道具は空気であるべきだという彼の結論が、最も小さく最も堅固に表れた決定である。

## なぜ SIer の上流工程が変わるのか — 決定の民主化とそのコスト

熊井の命題 — 「AI で速くなるほどボトルネックは上流へ移動する」 — が日本の SI 業界で重い反応を得た理由は、その業界の構造と正確に噛み合うからである。日本 SIer の伝統的な構造で、上流工程 (要件定義·基本設計) は最も高価な人材 (PM、コンサルタント、上級 SE) の時間で埋められる。下流工程 (実装·テスト) は協力会社あるいはオフショアのより安価な人材の時間で埋められる。この二層の費用差が日本 SIer の収益構造を作ってきた。

AI が下流工程の費用を 0 に収束させると、この構造は崩れる。Claude Code と Cursor の実測データがそれを可視化する。一人のシニアエンジニアが従来 5 人チームの実装作業量をこなす。日本 SIer の多層下請け構造が抱えていた費用差が一段狭まる、ということだ。狭まった場所は上流工程の付加価値である。だから 「AI で速くなるほどボトルネックは上流へ移動する」 という熊井の一行が、SIer 業界の自分の立場で最も強く読まれる。

上流工程の付加価値が大きくなるとは何を意味するか。熊井の振り返りが最も明確に突く。「要件定義は 『整理する工程』 から 『決断する工程』 へ変わる」 。従来の要件定義は (a) 顧客の散らかった発言を整理し、(b) それを標準フォーマットの文書に変換することが主な労働だった。その労働の 90 % が AI で自動化される時、残る仕事は (c) 何を作るかの決定だけである。決定は様式化できない。決定は責任を引き受ける。決定は政治的だ。

この変化が生む第二のコストがある。熊井が振り返りで直に突く。「全員が 『何を作るか』 を定義する場面に立たされる」 。従来の SIer では決定は PM 一人、コンサルタント一人の仕事だった。決定の民主化が起きる場所で、決定の合意コストが爆発する。ビジネス側、エンジニア、デザイナー、顧客側担当者 — それぞれの視点が同じ会議室で衝突すれば、決定の速度はかえって遅くなりうる。AI が作った速い選択肢が多く頻繁に提供されるほど、決定の負担が大きくなる。

熊井が振り返りに書いたもう一行がそのコストを突く。「社内の一部チームで AI に懐疑的な意見が多く、段階的導入を余儀なくされた」 。導入への政治的抵抗が、道具の効用とは無関係に導入速度を決める。何を作るかを決める場所に誰が座るのか、従来の決定者がその席を譲る意思があるのかという政治的な問いが付いて回る。熊井が BYOK 無料化を決めた際、社内で 「せっかく作った製品をなぜタダにするのか」 という反発にぶつかった逸話も同じ文脈である。決定の民主化は、決定者の立場から見れば権限の分散だ。

## 含意と展望 — 受ける側 SIer の次の一歩

熊井の振り返りが実務者に与える含意は三つに整理される。

**第一に、上流工程の再構成。** 従来の要件定義書一冊を 1 か月かけて書くパターンは事実上の終わりだ。新しいパターンは 「0 日導入された動くシステムの上で、会議ごとに 1 時間単位の要件を決定する」 である。このパターンで最重要の道具は、ドキュメント編集器ではなく、会議メモ → 決定 → 動く骨格に即時反映 → 次の会議の入力資料というサイクルを生むパイプラインだ。SIer の PM が今後 1 年で習得すべき道具がまさにこれである。

**第二に、決定者側の新しい負担。** AI が提供する速い選択肢が増えるほど、決定者の様式が評価の対象になる。従来の決定者は情報不足の環境で一行の決定をする仕事だったが、新しい決定者は情報過剰の環境で一行の決定をする仕事だ。二つは同じ仕事ではない。後者は、より多くの情報の中でシグナルとノイズを区別する能力を要求する。決定者側の人材像が変わっている。

**第三に、道具市場の新しい均衡。** 熊井の BYOK 無料化決定は日本市場の一つのシグナルである。従来の日本 SaaS の強い月額モデルの上で、道具の真の民主化は無料化へ向かう。これはグローバル市場の GitHub Copilot · Cursor · Claude Code と同じ流れを持つ。日本の社内統合ツール市場 (Notion、Slack、Confluence の日本市場シェア) に LLM 統合が標準となる時点で、誰が無料 + BYOK の席を先に取るかが、今後 2 年の変曲点になる。

楽観的シナリオは、SIer が速やかに上流工程を再構成し、決定の民主化を自身の付加価値として吸収する風景だ。悲観的シナリオは、従来の決定者が権限分散に抵抗して変化を遅らせ、その間にグローバルツールが日本 SIer の上流市場を奪う風景である。現実的な風景はその中間のどこかにある。熊井の 3 年の振り返りが指す方向は明確だ。変化を止める道はなく、変化の速度を決めるのは道具ではなく決定者の意思である。

## 結論 — 道具が空気になる場所で

熊井の振り返りが 142 likes を集めた理由は、日本 SIer 一世代の自分の仕事への問いを、一人の実測が正確に突いたからだ。AI で開発が速くなるほど、何が我々に残るのか。熊井の答えは単純である。決定。そして決定という仕事は様式化できないから、その場所にいる人の付加価値はかえって大きくなる。

本当の問いはその次だ。その決定の場所に誰が座るのか。従来の PM か、新時代のビジネス側担当者か、自律 AI エージェントそのものか。三つの答えがすべて部分的に正しく、三つの答えがすべて今後 3 年で試される。その試験の真ん中で、熊井が堅く突く一行は変わらない。「道具は空気であるべきです。コストもロックインも意識させず」 。その空気の中で決定をどう下すかが、次の時代の本当の SIer の付加価値になる。この振り返り自体が、日本 SIer 業界が自身の次世代の仕事の定義を、初めて自分の語彙で問い始めたシグナルである。
