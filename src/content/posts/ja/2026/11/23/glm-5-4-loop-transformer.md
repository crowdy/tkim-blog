# GLM-5.4 とループトランスフォーマー — パラメータの代わりに深さを積む賭け

> 同じ層を何度も回してモデルを「より深く」するループトランスフォーマーは、パラメータスケーリングの次の軸になるのか。それとも測定可能な利得よりも、解釈不能性というコストのほうが大きい迂回路なのか。

## 導入

2026年11月23日、中国の Z.ai（智譜、Zhipu）が「GLM-5.4: Toward generalized coding with our first loop transformer」を公開した。Hacker News では1,174ポイント、380件あまりのコメントを集め、その日の上位に入った。発表の核心はモデル名よりもアーキテクチャにある。GLM-5.4 は GLM-5 ベースモデルの28層を2回繰り返し実行するループトランスフォーマー（Loop Transformer）であり、Z.ai はこの構造によって750B 規模のモデルが2T〜3T パラメータのモデルに匹敵する知能水準に達したと主張している。

興味深いのは、発表文が何を載せ、何を載せなかったかである。アーキテクチャの説明は異例なほど詳細だ。ゲート、KV キャッシュ、スパースアテンションのインデックス再利用まで、設計上の選択を一つずつ明かしている。一方で、フラッグシップモデルのベンチマーク数値はない。公開された定量的な結果は、30B モデルでの統制実験の表と出力長の削減率くらいである。そして自ら限界を明記している。過度に長い「マラソン思考（marathon thinking）」のループに陥りがちだ、というのである。本稿は GLM-5.4 をきっかけに、ループトランスフォーマーという設計が何を得て何を支払うのか、そして HN コミュニティがなぜ熱狂と懐疑のあいだで割れたのかを分析する。

## GLM-5.4 は何を変えたのか

標準的なトランスフォーマーでは、各層は1回の順伝播につき1回だけ実行される。ループトランスフォーマーは、重みを共有する層の束を何度も繰り返し実行し、前のパスの隠れ状態を磨き上げていく。パラメータ数を増やさずに、より深いネットワークを得るわけだ。Z.ai 自身も、このアイデアが新しくないことを認めている。2018年の Universal Transformer が重み共有による深さを提案し、近年の recurrent depth や looped LM の研究が小規模で利得を示してきた。ただし、最初からループ構造で事前学習したモデルは、同じ事前学習の計算予算のもとでは重みを共有しないモデルに後れを取る、というのがこれまでの経験則だった。

Z.ai の解法は、ゼロから学習しないことである。すでに事前学習済みのベースモデルを、継続学習（continued training）によってループ構造に適応させた。この方式により、比較的小さな計算負担で知能の上限を引き上げられたと説明している。750B 規模で性能とデプロイコストのバランスを取るため、三つの変更を加えた。

第一に、**ゲート付き漸進的更新（Gated Progressive Updates）**。既存モデルの中間層をマルチパスのループに変える際、隠れ状態をそのまま上書きすると、反復のたびに活性値のノルムが暴走し、下流の層が想定外のスケールと分布の表現を受け取ることになる。GLM-5.4 は反復ごとにトークン単位の独立したゲートを設け、候補となる更新を残差ストリームに比例的に書き戻す。学習後のゲートには明確な分業が生まれたという。最初のパスは大域的な文脈を構築し、小さなゲート値で控えめに書き込んでスケールを安定させる。2回目のパスはその状態を再利用して出力を仕上げ、ゲートを開いて更新を全面的に書き込む。難しいトークンほど最初のパスがより積極的に書き込み、反復による精緻化の恩恵を大きく受ける。

第二に、**ハイブリッド KV キャッシュ**。素朴に実装すると、ループごとに完全な KV キャッシュを保持するため、メモリ使用量がループ回数分だけ掛け算で増える。GLM-5.4 では、2回目のループが1回目のパスで選択されたスパースな KV を再利用し、新たに生成した KV はスライディングウィンドウ内でのみ保持する。その結果、追加ループのコストはコンテキスト全体のキャッシュではなく、スライディングウィンドウ一つ分で済む。1M コンテキストでも、GLM-5.3 に対するデプロイコストの増加を十分に抑えられたという。

第三に、**スパースアテンションのインデックス再利用**。ベースモデルはスパースアテンションを採用しているが、2回目のループは1回目のループのインデクサが生成したアテンションインデックスをそのまま再利用し、インデックス計算のオーバーヘッドをゼロにする。毎パス再計算する場合とほぼ同等の性能だったとしている。

検証手順も公開されている。1B、4B、30B、750B のベースモデルで段階的にループ構造を検証し、750B と同一構造の30B モデルで、パラメータ数を揃えたうえで総学習計算量だけを約10%増やした統制比較を行った。利得は数学、科学的推論、長コンテキストで最も大きく、GPQA-Diamond や MMLU-Pro など大半のベンチマークで平均出力長が10〜14%短くなった。Z.ai はこれを「推論の一部が明示的な出力トークンから、ループの暗黙的な深さへ移った」と解釈している。推論速度はオフピーク時に最大で毎秒200トークン、ピーク時でも毎秒70〜80トークンを維持するという。重みは「必要な安全性強化を終えた後、責任ある形で」公開する予定であり、API は準備中である。

## なぜ今ループなのか、そして何を支払うのか

なぜこの設計が今出てくるのか。HN で多くの共感を集めたある説明は、推論ハードウェアのボトルネックから出発する（直接の引用ではなく要旨の整理）。トークンを一つ生成するには、層の重みを HBM からチップへ運び、一度計算して送り出す必要があるため、推論の最大のボトルネックはメモリ帯域である。同じ層を何度も計算すれば帯域への依存を減らしつつ、推論中に遊んでいた GPU の演算能力を知能に変えられる、という論理だ。別のコメントは、計算資源に制約を受ける中国企業が「必要は発明の母」とばかりにこの方向を押し進めている、と解釈した（要旨の整理）。パラメータを際限なく増やせない側が、深さという別の軸を探すのは自然な流れである。

Z.ai 自身の論理は少し異なる。GLM-5.3 の技術ブログで述べたとおり、記憶集約的なタスクにはパラメータが、推論集約的なタスクには実効計算量が効く。大規模なソフトウェアエンジニアリング、サイバーセキュリティ、3D モデリング、物理制御は、いずれも長い因果の連鎖をたどりながら大域的な論理一貫性を保たねばならない超長鎖の推論タスクであり、パラメータを積んでデータを暗記するだけでは解けない、という主張である。これが発表のもう一つのキーワード「Generalized Coding」につながる。コードを動画の生成・編集、ゲーム制作、FreeCAD での6軸ロボットアーム設計、GLSL シェーダーによる3D 体験といった領域にまで広げようという構想だ。

しかし、コスト側の帳簿もある。HN の懐疑論は三つの系統に整理できる。

第一に、**測定の不在**。最も繰り返された反応は「ベンチマークがなければ判断できない」というものだった（複数のコメントに共通する空気の要約）。2T〜3T モデルとの比較は主張にすぎず、デモは選り抜きであり、公開された数字は30B モデルの表と出力長の削減率だけだ、という指摘である。あるユーザーは外部のベンチマークへのリンクを示し、GLM-5.3 よりわずかに良いが常にそうではない、と伝えた（要旨の整理。当該の数値は本稿では検証していない）。

第二に、**ループの実益に対する根本的な疑問**。あるコメントは、ループモデルの利点は理論的で、欠点は実務的だとまとめた（要旨の整理）。事実上ループ回数を固定しなければサービングが難しく、学習計算量も推論計算量も減らしてくれない。実質的な利点は、既存モデルを継続学習で改造できる点だけだというのである。GLM-5.4 は2回目のパスの設計に強く結びついており、一般的な意味でのループというより重み共有に近い、という評価も付いた。これに通じる観察として、ゼロからループで学習したのではなく事前学習モデルを改造したものなので、同じ改造を施したモデルが今後大量に出てくるだろう、という予測もあった（要旨の整理）。

第三に、**解釈可能性のコスト**。最も重い批判は安全性の側から出た。ループトランスフォーマーは思考の連鎖（CoT）の監視可能性を崩す、というものだ（要旨の整理）。これまで LLM が何をしているかを覗き込む主な手段は、テキストとして出力される推論過程だった。ところが Z.ai 自身が「推論の一部が出力トークンからループの暗黙的な深さへ移った」と書いている。利得として示された出力長10〜14%の削減は、見方を変えれば、人間が読める推論がそれだけ減ったということでもある。効率と監査可能性が正面からぶつかる地点である。

実利用の面での不満もある。中国製モデルの「マラソン思考」は、単純な作業でも自分を疑い続けさせ、完了までの時間を大きく延ばす、という体験談が高い共感を得た（要旨の整理）。Z.ai が限界として明記した、まさにその現象である。出力トークンが減ったという主張と、思考ループが長引くという限界が一つの発表の中に同居していることは、この設計の挙動がまだ完全には飼い慣らされていないことを示している。

## 展望と実務への示唆

この発表をどう読むべきか。発表文の最後の一文がヒントになる。Z.ai は、深さのスケーリングとモデルサイズのスケーリングのどちらかを選ぶのではなく両方を追求するとし、GLM-5.4 は計算の深さを検証したものであり、「はるかに大きな次のモデル」がまもなく用意できると書いた。HN でも GLM-5.4 を GLM-5.5 のプレビューと見る向きがあった（要旨の整理）。つまりこれは完成品の発表というより、アーキテクチャの検証報告に近い。ベンチマークの不在も、その性格と無関係ではないだろう[仮定]。

シナリオを分けてみよう。

- **楽観:** 既存の事前学習モデルを継続学習でループ化するレシピが再現可能なら、巨大な事前学習をやり直すことなく知能の上限を引き上げる低コストの経路が開ける。計算資源の限られた研究所やオープンウェイト陣営には特に有利だ。適応的計算（難しいトークンにより多くの反復を割り当てる）まで実現すれば、「考えるべきぶんだけ考える」モデルに近づく。
- **悲観:** 独立したベンチマークで利得がわずかだと判明し、固定ループのサービングの複雑さとマラソン思考の遅延コストだけが残る。同時に、CoT 監視可能性の後退が業界の慣行として定着してしまう。
- **現実的:** ループは万能の軸ではなく、特定のタスク群（数学、長期推論）で費用対効果のある道具として定着する。性能競争が深さの方向へ移るぶん、推論過程の可視性をどう補うかが別個の研究・規制上の課題になる。

実務者への示唆は次のとおりである。第一に、モデル選定の際に「出力トークンの削減」を純粋なコスト削減とだけ読まないこと。推論ログを監査やデバッグに使うワークフローなら、可視性の低下はコストである。第二に、レイテンシの分布を自分で測定すること。毎秒トークン数の上限（200）とピーク時（70〜80）の差、そしてマラソン思考によるテールレイテンシは平均値には現れない。HN には、上位プランでも並列レビュアーの多くがレート制限に引っかかったという報告もあった（要旨の整理）。第三に、利用経路を確認すること。発表時点で通常の API は「Coming Soon」であり、Simon Willison 氏は通常の API プランではなく Coding Plan のキーでしか新モデルにアクセスできなかったと HN に書いている（要旨の整理）。日本の開発現場で GLM 系を検証用に回している組織は、この経路の違いが評価環境の再現性に影響する点にも注意したい。

## 結論

リード質問に戻ろう。ループトランスフォーマーはパラメータスケーリングの次の軸なのか。GLM-5.4 が示したのは「可能性の証拠」であって「優位の証拠」ではない。750B 規模で事前学習モデルをループに改造しても活性値が暴走しないようにするゲート、メモリコストをスライディングウィンドウ一つに抑える KV 設計、インデックスの再利用は工学的に意味のある貢献であり、それを詳細に公開した透明性は HN でも高く評価された。しかし、2T〜3T 級という主張を裏付ける公開の数字はまだない。

より根本的な問いは別にある。推論を出力トークンから隠れ状態の反復へ移すことは、効率の問題であると同時に観測可能性の問題でもある。私たちがこれまでモデルの「思考」を読めたのは、モデルが思考を文章として書かざるを得なかったからだ。ループはその強制を少しずつ緩めていく。読者に残したい問いはこうである。あなたのシステムにおいて、モデルの推論ログはコストなのか、安全装置なのか。そしてそのログが10%短くなったとき、それは節約なのか、損失なのか。
