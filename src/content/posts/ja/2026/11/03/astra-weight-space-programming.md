# AstraがQwenの重みを直接書き換えた — 勾配なしでモデルを直す ということ

> 勾配降下法なしでモデルの重みを直接読み書きし、能力を変えるというのは、新しい種類の最適化なのか、それともまだ検証されていない主張なのか。

## 導入

2026年11月3日、「Astra can read and write weights to improve Qwen」と題されたブログ記事がHacker Newsで2,136ポイント、コメント696件という記録的な反響を呼んだ。この記事は、GPT-6 Astraというフロンティアモデルが他のニューラルネットワークの重みをPythonセッション内で直接のぞき込み、勾配降下法やオプティマイザなしに特定の方向を修正することで、小さなモデルの振る舞いを変えた一連の実験を紹介している。著者らはこれを「重み空間プログラミング(weight-space programming)」と呼ぶ。モデルがネットワークの各部分が何を計算しているかを推論し、重みを直接編集する方式で、環境からのフィードバックが一切ない場合もあった。

最も注目を集めた実験は8番目のものだ。Qwen3.5-0.8Bはモデルカードでも警告されている持病のような「反復ループ」に頻繁に陥るが、Astraはこのモデルの重みとGSM8K・MATHの練習問題、限られた回数の順伝播(forward pass)だけを与えられた状態で、反復ループの原因を15層目と19層目のMLPが書き込む特定の一方向にまで突き止めた。その方向を特定の出力列から取り除くと問題は解消した。この過程で修正された重みは131,072個、全体の0.016%に過ぎず、学習は一切行われなかった。単一の方向をひとつ重みから削除するだけで、ひとつの振る舞いを取り除いたことになる。

## 実験が示したこと

著者らが公開した実験群は大きく読む・直す・新しく書くの三つに分かれる。読む実験(1~3、7番)では、Astraはポリシーネットワークの重みだけを見て、それがどのゲームで学習されたか、小さなトランスフォーマーがどの言語で学習されたかを識別し、コピーヘッド(copying head)を見つけ出した結果は実測値と一致した。ただしすべての読み取り実験が成功したわけではない。おもねる(sycophantic)モデルを重みだけから検出する試みは失敗し、Astraがアテンションパターンまで覗けるようにして初めて成功した。

直す実験(4番)では、坂道で止まってしまった車両ポリシーが局所最小値に陥っている問題を、重みのわずか3.5%を修正するだけで直した。1,024回のテストエピソードすべてで成功したというのが著者らの主張である。新しく書く実験(5~6番)はさらに大胆だ。Breakoutゲームで一切学習を経ていないネットワークが517.4点を記録したが、これは1億ステップ学習したPPOの15.8点を圧倒する数値である。SeaquestとAsterixでは5億ステップのPPOに迫る性能を見せ、9×9の囲碁では順伝播を一度も経ずに、より小さなPPOネットワーク相手に半数を超える勝率を記録し、順伝播を50回経た後には同サイズのPPOネットワークにも勝った。

8番目の実験、すなわちQwenの数学性能改善の数値は次の通りだ。MATH-500のスコアは7.9%から48.1%へ、GSM8Kは13.8%から67.1%へ、IFEvalは21.0%から62.3%へ上昇し、トークン上限に達して答えを完結できない割合は93%から33%に減った。ただし著者らは負の結果も合わせて公開している。反復ループにほとんど陥らないGemma 3 270Mには同じ方法を適用しても数学性能は改善しなかった。これについて著者らは「重み編集は障害物を取り除くことはできても、存在しない能力を新たに追加することはできない」と結論づけた。この負の結果を自ら公開したという点は、この研究が結果を誇張しないための最低限の節度を備えているシグナルとして読める。

## HNの懐疑論 — 誇張された結果か、本物のブレークスルーか

HNでの議論の大部分は、この結果に対する鋭い懐疑論で占められた。yurimoはこのブログ記事が結果を誇張していると指摘し、重み編集と解釈可能性研究はすでに3年近く進められてきた分野であり、実験に使われたモデルは約2万パラメータ規模と非常に小さく、数学の「改善」と呼ばれる結果の多くは実質的に失敗に近いと主張した。l9oはさらに具体的に、Qwenはそもそも数学を「知って」いたと指摘した。実際の問題は無限ループに陥りトークン上限に引っかかったことだけであり、まさにそれゆえループにほとんど陥らないGemma 3 270Mには同じ方法が通用しなかったのだという。pamaはさらに踏み込み、チューニングされていないQwen 0.6BモデルがむしろMATH-500で最終的な「修正済み」モデルより高いスコアを記録したと報告し、7.9%というベースライン数値自体が設定ミスである可能性を提起した。続くコメントでは、チューニングされたモデルがむしろ以前の学習段階より性能が劣るという指摘も出た。

theptipは複数の実験が入り混じって提示されたことで全体の印象が水増しされたと評価した。数学の結果は古典的なステアリングベクトル(steering vector)介入の一例に過ぎず、論文は数学的能力が「どのように」機能するかについての機構的理解を新たに加えてはいないという。BoorishBearsは実験同士が互いに積み重なっていないと指摘した。Qwenに移った瞬間、Astraにできたのは数値だけの重みを使った作業のみだったという。Aurornis、GuB-42、hgoelは口をそろえて、これは本質的に「アブレーション(ablation)」技法を別の振る舞いに適用したものに過ぎないと評価し、freakynitはすでに広く使われているアブレーションツールであるHereticプロジェクトを根拠に挙げた。

Astraが実際に「どのように」この作業をやり遂げたのかが不透明だという疑問も繰り返し提起された。cloudbonsaiとVaushiteは、Astraの内部推論過程が隠されているため、論文に記録されたツール呼び出し以外に実際に何をしたのかわからないと指摘した。Vaushiteは特に、Astraがクライアント側のツールを呼び出さなかったという事実だけが確認されるにすぎず、その内部過程自体は観察されていないと指摘した。__MatrixMan__はより根本的な問いを投げかけた。より賢いモデルが自分の知っていることをより弱いモデルに分け与えることは、それ自体としてはAI能力全体の天井を引き上げることにはならないというのだ。つまりAstraがQwenを直したのは知識の「移転」であって知識の「創造」ではないという批判である。一方radicalbyteは、この作業方式を8ビットゲームのチートコードを探していた時代に喩えた。メモリを丸ごとダンプし、値を変えてテストし、結果を比較する古典的なリバースエンジニアリングの手法と本質的に変わらないというのだ。user43928は興味深い再現事例を伝えた。Claude Opusをウェブインターフェースで使っても、重みだけからBreakoutのネットワークを識別できたという報告である。これはこの能力が少なくとも部分的には論文特有の実験設計に閉じたものではなく、他の環境でも再現可能であることを意味する。

既存手法との比較も盛んだった。augment_meはこのアプローチがLoRAやGRPOのような既存の事後学習(post-training)手法を代替できるかもしれないと見たが、著者らがこの方法にかかる計算コストを明示していない点を問題視した。giancarlostoroはLoRAをマージする作業自体がすでに安価であるため、比較の公正さは分析に投入された計算量をどれだけ正確に数えるかにかかっていると指摘した。再現性への疑問も続いた。l9oとepihelixはそろって、この方法がループにほとんど陥らないGemma 3 270Mでは失敗したという事実を挙げ、すべてのモデルに一般化される技法ではないと釘を刺した。ch_smはそれでも20B~70B規模のローカルモデルで専門化されたクラスターを自動的に識別し学習の誤りを修正する能力は印象的だと評価したが、この記事の実験の大半はそれよりはるかに小さいモデルで行われており、ch_smが期待する規模での検証はまだなされていない。

## 展望と示唆 — 解釈可能性と安全性という二つの軸

この結果を解釈可能性研究の延長線上に見る視点もあった。ninglorはAstraがBreakoutのネットワークを読み解いた過程を、入力層と出力層をマッピングしどの重みが意味を持つかを察知する方式として説明し、ACCount39は異なるモデル間で観察される重みの類似性をプラトン的表象仮説(Platonic Representation Hypothesis)と結びつけた。HAL3000はさらに踏み込み、重みそのものが一種の内部言語として機能しうるとし、異なるネットワークが見た目は違っても数学的に等価な表象を通じて同じ問題を解いている可能性があるという仮説を示した。この視点から見ればこの実験は単なる性能改善のトリックではなく、ニューラルネットワーク内部の「言語」を別のニューラルネットワークが読み取れるという可能性を示した事例として読める。

安全性に関する懸念はより具体的だった。Buttons840はこれこそがこれまで警告されてきた「再帰的自己改善(recursive self-improvement)」の事例だと評価したが、その強い版については自らも懐疑的だと付け加えた。solid_fuelはさらに鋭く反論した。今回の実験でモデルが直したのは自分自身ではなく自分より小さいモデルだったため、「自己(self)」という表現も、より大きなモデルでは失敗したため「再帰的(recursive)」という表現もどちらも成立しないというのだ。nightshift1は同じアプローチが実際のフロンティア級の大型モデルにも通用するかは今回の実験だけではわからないと指摘した。XCSmeはこのように編集されたモデルが実際に何をしているのかを理解し安全規則を強制する方法への懸念を提起し、swiftcoderはこの技法がジェイルブレイクと構造的に似ているため、今後こうした編集を防ぐ安全装置が生まれるだろうと予測した。0xbadcafebeeはこの方法がファインチューニングのコストを大幅に下げうるという点で、性能向上の利点と同じくらい悪用の敷居を下げる副作用も伴いうると警告した。著者ら自身もこの限界を把握していないわけではない。現在はコンテキスト長とモデルを扱うハーネス(harness)の制約から検証可能なモデル規模が限られていると明かし、この技法を体系的に検証する専用ベンチマークを構築中だと付け加えた。つまり現在公開されている結果は完結した証明というより、さらなる検証を要する初期探索段階の報告書に近い。

## 結論

この実験が実際に意味のあるブレークスルーなのか、それとも選択的に選ばれたベンチマークで装飾された誇張なのかは、現時点では断定できない。Breakoutでの圧倒的なスコアやQwenの数学性能改善は確かに印象的だが、pamaが提起したベースライン設定ミスの可能性と、Gemma 3 270Mでの明白な失敗は、この結果を額面通りに受け取ることを難しくする最も重要な歯止めである。むしろこの研究で最も信頼に値する部分は華々しい成功事例ではなく、著者ら自身が「重み編集は存在しない能力を追加できない」と認めた負の結果なのかもしれない。重み空間を直接読み書きする技法が、解釈可能性研究と低コストなモデル修正という二つの道のどちらに続くのかは、今よりはるかに大きなモデルでの独立した再現実験を待って初めて答えられる問いである。
