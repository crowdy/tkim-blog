# IDEの黄昏 — AIコーディングエージェント時代、開発者はIDEを離れつつあるのか

> VS Codeを最後に開いたのがいつだったか思い出せない。IntelliJのライセンス更新メールが届いても無視している。Claude Codeがターミナルですべてを解決し始めてから、IDEは私のワークフローから静かに消えていった。しかし、そう感じていたのは私だけではなかった。

---

## 1. 私だけなのか？

正直に言うと、最初は不安だった。IDE抜きで開発するというのは、まるでシートベルトなしで運転するような気分だった。オートコンプリート、デバッガ、Git統合、リファクタリングツール — すべてがIDEの中にあり、それを手放すのは生産性の後退のように感じられた。

ところがClaude Codeを使い始めて状況が変わった。コードを読み、修正し、テストし、コミットする全プロセスがターミナルひとつで完結した。ファイルツリーをマウスでクリックする必要も、タブを10個も開いておく必要もなかった。「この関数をリファクタリングして」と言えば、コンテキストを自ら把握し、関連ファイルを見つけ、修正し、テストまで回してくれた。

Redditのr/programmingにはこんな投稿が溢れている。

> 「I haven't opened VS Code in 3 weeks. Claude Code + tmux is my IDE now.」

> 「Cancelled my JetBrains subscription. Between Claude Code and vim, I don't need it anymore.」

Hacker Newsでも似たような告白が続いている。「IDEを使わなくなったのではなく、IDEを使う理由を見つけられなくなった」というのだ。これは単なるトレンドではない。数字がそれを証明している。

---

## 2. 数字で見るIDE市場の地殻変動

### Stack Overflow 2025 Developer Survey

Stack Overflowが2025年に発表した開発者アンケートの結果は、IDE市場の変化を鮮明に映し出している。

| 順位 | ツール | 使用率 | 備考 |
|------|--------|--------|------|
| 1 | VS Code | 75.9% | 依然として圧倒的1位、ただし成長は停滞 |
| 2 | Visual Studio | 28.3% | .NETエコシステム中心 |
| 3 | IntelliJ IDEA | 27.5% | JVMエコシステム主力 |
| 4 | Notepad++ | 24.2% | ライトエディタの需要は健在 |
| 5 | Vim | 22.2% | ターミナル回帰のシグナル |
| **6** | **Cursor** | **17.9%** | **新規参入、初年度で6位** |
| 7 | Neovim | 16.1% | Vimと合算で38.3% |
| - | Claude Code | ~10% | ターミナルベースのAIコーディング |

注目すべきポイントが3つある。

**第一に、Cursorの登場。** 2024年には存在しなかった名前が一気に6位に躍り出た。初年度で17.9%という数字は、開発者ツール史上前例のない速度だ。

**第二に、Vim/Neovimの復活。** 両ツールを合算すると38.3%で、前年比で明確な上昇トレンドにある。これは「ターミナルへの回帰」というより大きな潮流の一部だ。AIコーディングエージェントがターミナルで動作するようになり、開発者も自然とターミナル中心のワークフローへ移行しつつある。

**第三に、VS Codeの停滞。** 75.9%という数字は依然として圧倒的だが、成長が止まった。市場が飽和したのではなく、代替手段が生まれたのだ。

### JetBrains DevEco 2025

JetBrainsのDeveloper Ecosystem Survey 2025は、さらにドラマチックな数字を示している。

- **Cursorユーザー：17倍増** — 2024年の約135名から2025年には2,300名以上に急増
- **65%の開発者が週1回以上AIコーディングツールを使用** — 2023年の40%から急増
- AI支援コードの割合がコードベース全体で継続的に増加

これらの数字が語っているのは明確だ。**AIコーディングツールが「あれば便利なもの」から「ないと不便なもの」へと転換したということだ。**

---

## 3. 三強構図 — Copilot、Cursor、Claude Code

AIコーディングツール市場は2025〜2026年にかけて、3つの巨人が支配する構図へと再編された。市場全体の規模は約$4-5B（約6,000〜7,500億円）と推定され、この3社が70%以上を占めている。

### GitHub Copilot — 先行者の重み

| 指標 | 数値 |
|------|------|
| ユーザー数 | 2,000万+ |
| 市場シェア | ~42% |
| 親会社 | Microsoft (GitHub) |
| 統合環境 | VS Code、JetBrains、Neovimなど |

Copilotは2021年の初登場以来、AIコーディングの代名詞だった。VS Codeとのネイティブ統合、Microsoft/GitHubエコシステムの力、そして2,000万という圧倒的なユーザーベースは依然として強力だ。しかし2025年から成長速度が鈍化し始めた。機能面ではオートコンプリート中心からエージェンティックコーディングへの転換を試みているが、後発に比べて体感できるイノベーションが少ないという評価が多い。

### Cursor — SaaS史上最速の成長

| 指標 | 数値 |
|------|------|
| ARR | $2B（2025年） |
| バリュエーション | $29.3B |
| ARR $100M達成 | リリースから16ヶ月 |
| ベース | VS Codeフォーク |

Cursorの成長曲線はSaaS史上前例がない。$100M ARRを16ヶ月で達成し、そこからわずか1年足らずで$2B ARRを記録した。VS Codeをフォークし、AIをコアに内蔵する戦略が的中した。開発者は馴染みのあるVS Codeインターフェースを維持しながら、AI機能を「付加機能」ではなく「コア体験」として利用できるようになった。

2026年にはCursor 2.0をリリースし、自社モデルの開発、使用量ベースの課金モデルへの移行を進めている。「エディタ」企業から「AIコーディングプラットフォーム」企業への進化だ。

### Claude Code — ターミナルという新たなパラダイム

| 指標 | 数値 |
|------|------|
| ARR | $2.5B（Anthropic AIコーディング売上） |
| 開発者満足度 | 46%（1位） |
| インターフェース | ターミナル（CLI） |
| 特徴 | エディタ不可知論（editor-agnostic） |

Claude Codeが最も興味深い存在である理由は、**IDEを代替するのではなく、IDEを不要にするという点**だ。CopilotがIDEの中に入り込み、CursorがIDE自体を再発明する一方で、Claude Codeは**IDEの外で**動作する。

開発者満足度調査で46%を獲得し1位となったことは示唆的だ。ユーザー数ではCopilotに遠く及ばないが、実際のユーザー満足度は最も高い。これはClaude Codeが提供する体験が質的に異なることを意味している。

ターミナルで自然言語で対話しながらコードを書く体験は、IDEでタブ補完を受けるのとは根本的に異なるパラダイムだ。以前は開発者がコードを「書いて」いたが、今は意図を「伝えて」いる。

## 4. 「IDEは死んだ」vs「IDEは変わる」

AIコーディングエージェントの台頭とともに、開発ツールの未来をめぐる議論が白熱している。両極端の主張が真っ向からぶつかり合っている。

### 「IDEは2026年までに消える」

Googleの伝説的エンジニアSteve Yeggeは2025年末、自身のブログで衝撃的な予測を発表した。

> 「Traditional IDEs will be irrelevant by end of 2026. The agent is the IDE.」

彼のロジックはこうだ。IDEのコアバリュー — オートコンプリート、リファクタリング、デバッグ、ナビゲーション — はすべてAIエージェントがより上手くこなせるものだ。コードを「構造的に理解」してASTベースのリファクタリングを行うよりも、コードの「意図を理解」して全体的な再設計を行う方が強力だ。IDEの機能はAIエージェントの下位互換（subset）に過ぎないというのだ。

### 「コードのビジュアルインターフェースは消えない」

反対側にはZedエディタの創始者Nathan Soboがいる。

> 「Agents are powerful, but developers will always need to see, navigate, and understand code visually. The visual interface isn't going away — it's being augmented.」

コードのビジュアルな探索、diffの比較、アーキテクチャの空間的理解 — こうしたことはターミナルのテキストストリームでは代替できないという主張だ。IDEは死ぬのではなく、AIエージェントをオーケストレーションする新たな役割へと進化するというのだ。

### 不都合な真実 — 体感と実態のギャップ

この議論をさらに複雑にする研究がある。AI安全研究機関METR（Model Evaluation & Threat Research）が2025年に発表した実験結果だ。

> **体感速度：20%速くなったと感じた。実際の速度：19%遅くなっていた。**

熟練したオープンソース開発者16名が参加したランダム化比較実験で、AIコーディングツール（Cursor Pro + Claude 3.5 Sonnet）を使用したグループは、使用しなかったグループより**実際には19%遅かった。** しかし参加者は自分が20%速くなったと感じていた。

METRはこれを**「効率の幻想（Efficiency Illusion）」**と名付けた。AIが生成したコードをレビューし修正するのにかかる時間が、自分で書く時間より長かったのだ。

さらにコード品質の問題もある。GitClearの2025年レポートによると：

- 全コードの**41〜46%がAIによって生成**
- AI生成コードは人間のコードと比較して**1.7倍多くのイシュー**を発生
- セキュリティ欠陥率：AIコードの**24.7%**でセキュリティ脆弱性が発見

これらの数字は「IDE無しでAIだけで十分だ」という主張に冷や水を浴びせる。AIコーディングエージェントが強力なのは事実だが、生成されたコードを検証し理解するためのツールの必要性も同時に高まっているということだ。

## 5. IDE企業の対応戦略

伝統的なIDE企業はこの変化にどう対応しているのか。各社の戦略は驚くほど異なる。

### JetBrains — 「我々がエージェントを作る」

JetBrainsの対応は最もドラマチックだった。

2024年に意気込んでリリースした次世代エディタ**Fleetを廃止**した。VS Codeに対抗するために作った軽量エディタだったが、AIコーディングエージェントの登場により戦略自体が無意味になったためだ。代わりに全く新しい方向へと舵を切った。

- **Junie**：JetBrainsのAIエージェント。IntelliJ、WebStormなど既存IDEに統合され、自律的にコーディング作業を遂行する。
- **JetBrains Air**：2026年初頭に発表されたエージェンティック開発環境。「IDEがエージェントを支援する」のではなく、「エージェントがIDEを使う」というパラダイムの転換だ。
- **無料AIティア**：AI機能の基本アクセスを無料化し、有料AIコーディングツールへの流出を防御する。

JetBrainsのメッセージは明確だ。**「エージェント時代にもIDEは必要だ。ただし、エージェントのためのIDEに進化しなければならない。」**

### Microsoft — エコシステムの力で防衛

Microsoftは2つの戦略を並行している。

**攻め**：Copilot Chatをオープンソース化し、VS Code 1.109でマルチエージェント対応を導入した。ひとつのエディタ内で複数のAIエージェントが同時に作業できる環境を構築中だ。

**守り**：VS Code Marketplaceの拡張機能ライセンスを制限し、CursorのようなVS Codeフォークが公式拡張を使えないようにした。エコシステムを武器化したのだ。CursorがVS Codeの拡張エコシステムに依存しているという弱点を正確に突いた。

この戦略は議論を巻き起こした。オープンソースコミュニティからは「Microsoftがオープンソースの精神を裏切った」という批判が上がったが、ビジネス的には効果的な牽制だった。

### Cursor — エディタを超えてプラットフォームへ

Cursorは最も攻撃的な戦略を採っている。

- **Cursor 2.0**：自社AIモデルを開発し、外部モデルへの依存度を下げている
- **使用量ベース課金**：従来の月額定額モデルから使用量ベース（usage-based）課金へ移行し、ヘビーユーザーとライトユーザーを同時に取り込む
- **Background Agent**：IDEを開かなくてもバックグラウンドでAIが作業を行う機能を実験中 — 皮肉にもIDE自体を不要にしかねない機能だ

### Windsurf — 買収という出口

Codeiumが開発したAIコーディングエディタWindsurfは別の道を選んだ。Cognition AI（自律コーディングエージェントDevinの開発元）に**$250M（約375億円）**で買収された。独立したAIエディタとしての競争が困難だという判断だった。この買収は市場に強力なメッセージを送った。**独立AIエディタの時代は終わり、巨大なAIプラットフォームに統合される時代が来たということだ。**

### 共通点：「テキストエディタ」から「エージェントオーケストレーションプラットフォーム」へ

すべての企業の戦略にひとつの共通方向がある。IDEはもはや「コードを書くツール」ではない。**AIエージェントたちが協業するステージ**、すなわち「エージェントオーケストレーションプラットフォーム」へと変貌しつつある。コードの記述はエージェントが行い、IDEはそのエージェントを管理し結果を可視化する役割へと移行している。

## 6. 開発者の選択肢 — そして未来

### ツール断片化の時代

興味深い現象が起きている。開発者がひとつのツールを選ぶのではなく、**2〜3個のツールを同時に使う**のが当たり前になりつつある。Claude Codeでコードを生成し、VS Codeでdiffを確認し、Cursorでリファクタリングする — そんな具合だ。「最高のツール」ではなく「最適な組み合わせ」を探す時代になった。

### Vibe Coding — コーディングの民主化か、技術的負債の爆弾か

Collins Dictionaryが2025年の年間ワードに選出した**「Vibe Coding」** — 自然言語で意図を伝えるだけでAIがコードを生成する開発方式 — は$4.7B規模の市場を形成している。非開発者でもソフトウェアを作れる時代が到来したのだ。

しかしこれが「コーディングの民主化」なのか「技術的負債の民主化」なのか、まだ答えは出ていない。AI生成コードの24.7%でセキュリティ欠陥が見つかっているという事実は、vibe codingがもたらし得るリスクの大きさを示唆している。

```
# Vibe Codingの現実
開発者：「ユーザー認証機能を作って」
AI：（200行のコードを生成）
開発者：「動いた！デプロイしよう！」

# 3ヶ月後
セキュリティチーム：「SQLインジェクションの脆弱性が発見されました」
開発者：「…そのコード、自分が書いたんじゃないんだけど」
```

### IDEは死なない。だが、私たちが知っていたIDEはすでに消えつつある

結論を出してみよう。

IDEが完全に消滅する可能性は低い。コードのビジュアルな探索、複雑なデバッグ、大規模プロジェクトのアーキテクチャ理解 — こうした作業においてビジュアルインターフェースの価値は依然として健在だ。

しかし**IDEのアイデンティティ**は根本的に変わりつつある。10年前、IDEは「コードを書くツール」だった。5年前は「コードを書いてオートコンプリートを受けるツール」だった。今は「AIエージェントが書いたコードを検証し可視化するツール」へと転換しつつある。

そして私のような開発者 — Claude Codeひとつでコードを書き、レビューし、テストし、コミットする開発者 — は着実に増えている。我々はIDEを「離れた」のではなく、IDEが提供していた価値を**別の形で**受け取っているのだ。

ターミナルウィンドウひとつ、そして対話できるAI。それが2026年のIDEだ。
