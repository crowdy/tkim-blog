# crowdy-blog — Design Spec

**Date:** 2026-04-28
**Repo:** `github.com/crowdy/crowdy-blog`
**Live URL (target):** `https://crowdy.github.io/crowdy-blog/`
**Stack:** Astro + GitHub Pages + GitHub Actions

## Goal

Publish a multilingual personal blog from local markdown content authored at `~/dev/crowdy/blog/`. Posts are pre-existing essays in Korean, Japanese, and English (often paired translations). The site must support per-language post indexes, per-post language toggles for paired translations, dark mode, and a clean, text-first reading experience.

## Scope

### In scope
- Static Astro site deployed to GitHub Pages from `main` branch via GitHub Actions
- Three-language structure (`ko`, `ja`, `en`) with separate index pages and a per-post language toggle for paired translations
- Sync script that imports markdown from `~/dev/crowdy/blog/{root,posted,draft/}` into `src/content/posts/<lang>/`, generating frontmatter automatically
- Minimal text-first design with dark mode (system + user override) and code syntax highlighting
- Drafts visible in dev mode only; excluded from production build

### Out of scope
- Comments, search, pagination, RSS (can be added later — YAGNI)
- CMS / web editor (content stays as files in `~/dev/crowdy/blog/`)
- Visual regression / E2E tests
- Custom domain (subpath project Pages site is sufficient)
- Incremental sync (full regeneration is cheap at this scale)

|---|---|---|
| Root | 6 files | Three main posts × ko/ja pairs (`korea-ai-policy-review`, `midlife-engineer-peace`, `open-leadership`) |

Conventions:
- Plain markdown, no existing frontmatter
- File body starts with `# Title`
- An optional `> blockquote` after the title commonly serves as a lede
- Filename convention: `<base-slug>.md` for the primary language, `<base-slug>-ja.md` for Japanese pair (no `-ko` or `-en` suffix used)

### Data flow
1. Author writes/edits markdown in `~/dev/crowdy/blog/`
2. `npm run sync` regenerates `src/content/posts/` from source
3. `git commit && git push` to `main`
4. GitHub Actions runs `npm ci && npm run sync && npm run build` and deploys `dist/` to Pages
5. Visitors reach `https://crowdy.github.io/crowdy-blog/`

## Components

### `scripts/sync-posts.ts`

Node TypeScript script (run via `tsx`).

**Inputs:** files matching `~/dev/crowdy/blog/**/*.md`, excluding:
- Files starting with `.` (e.g. `.swp`, `.DS_Store`)
- Anything under `.claude/`

**Per-file processing:**

| Field | Source |
|---|---|
| `title` | First `# Heading` line in body. If missing, fallback to humanized filename + warn. |
| `description` | First `> blockquote` block; if absent, first paragraph; truncated to 200 chars. |
| `pubDate` | File `mtime`. |
| `lang` | Filename ends with `-ja` → `ja`. Else heuristic (see below). |
| `pairSlug` | `<base-slug>` with `-ja` suffix removed. |
| `draft` | `true` iff source path is under `draft/`; else `false`. |
| `sourceDir` | `root` \| `posted` \| `draft` (debug aid). |

**Language heuristic** (when no `-ja` suffix):
- Count Hangul (`가-힯`, `ᄀ-ᇿ`, `㄰-㆏`) characters / total non-whitespace characters.
- If ratio ≥ 0.30 → `ko`, else → `en`.
- Japanese-without-suffix is not expected per current convention; if Hiragana/Katakana ratio ≥ 0.30 it is classified as `ja` and a warning is logged (defensive).

**Output:** `src/content/posts/<lang>/<base-slug>.md` with generated YAML frontmatter prepended.

**Behavior:**
- Idempotent: same source tree → same output tree.
- Always wipes `src/content/posts/` first to prevent orphans.
- **Fail-fast on collision:** if two source files would produce the same `<lang>/<base-slug>.md`, log both paths to stderr and exit 1.
- Logs counts at end: `synced: N | skipped: M | warnings: K`.

### `src/content/config.ts`

Zod schema for the `posts` collection:

```ts
{
  title: z.string(),
  description: z.string(),
  pubDate: z.coerce.date(),
  lang: z.enum(['ko', 'ja', 'en']),
  pairSlug: z.string(),
  draft: z.boolean().default(false),
  sourceDir: z.enum(['root', 'posted', 'draft']),
}
```

Schema violations fail the build by design — bad frontmatter must surface.

### `src/utils/pairs.ts`

```ts
getPairs(allPosts, currentPost): { ko?: Post; ja?: Post; en?: Post }
```

Groups posts by `pairSlug` and returns siblings of `currentPost` keyed by language.

### `src/components/LangToggle.astro`

- Receives the pair map for the current post.
- Renders a button per available language; current language is marked active and not clickable.
- Hidden entirely when no other languages exist for that `pairSlug`.

### `src/components/ThemeToggle.astro`

- Default: respect `prefers-color-scheme`.
- User override stored in `localStorage` under `theme`.
- Inline script in `<head>` applies the theme before paint to avoid flash.

### `src/components/PostCard.astro`

Used in language index pages. Shows `title`, `description`, `pubDate`, and a small badge if a translation is available.

### Pages

- `src/pages/index.astro` — `<meta http-equiv="refresh" content="0; url=./ko/">`. (Default to ko.)
- `src/pages/[lang]/index.astro` — `getStaticPaths` returns `[{ params: { lang: 'ko' } }, …]`. Lists non-draft posts for that language, newest first. Drafts only appear when `import.meta.env.DEV`.
- `src/pages/[lang]/[slug].astro` — `getStaticPaths` enumerates every post. Renders `PostLayout` with `LangToggle` + body.
- `src/pages/404.astro` — minimal page with link back to `/ko/`.

### Layouts & styles

- `BaseLayout.astro`: sets `<html lang>`, includes ThemeToggle in header, footer with link to repo.
- `PostLayout.astro`: title, pubDate, LangToggle, then `<article>` body with prose styling.
- `global.css`: minimal CSS custom properties for light/dark, system font stack, comfortable measure (~70ch), Shiki-rendered code blocks (Astro default).

## Error handling

| Where | Case | Behavior |
|---|---|---|
| Sync | No `# Heading` | Warn; use humanized filename as title. |
| Sync | Language detection fails / ambiguous | Warn; default `en`. |
| Sync | Slug collision in same `lang` | **Exit 1** with both paths. |
| Sync | Empty / unreadable file | Skip + warn. |
| Sync | Output dir missing | Create. |
| Build | Frontmatter fails Zod | Astro build fails (intentional). |
| Build | Pair lookup empty | LangToggle renders empty / hidden — normal. |
| Build | Draft post in prod | Excluded from `getStaticPaths` and indexes. |
| CI | Build failure | Existing Pages deployment is preserved. |
| Runtime | Unknown URL | Custom 404 with link home. |

## Testing

**Unit (Vitest):**
- `parseFilename(name) → { baseSlug, lang }`
- `extractTitle(markdown)`
- `extractDescription(markdown)`
- `detectLanguage(content)` — covers `ko`, `ja`, `en`, ambiguous fallback, and the 30% boundary
- Fixtures live in `tests/fixtures/`

**Integration:**
- Build a temp source tree, run `sync()`, assert output file count and a sampled frontmatter set.
- Collision case asserts `process.exit(1)` (or thrown error in test mode).

**CI gate:**
- `npm run sync && npm run build` must pass.
- `astro check` (TypeScript strict) must pass.

**Out of scope:** browser E2E, snapshot tests, visual regression.

## Deployment

- Astro `output: 'static'`, `site: 'https://crowdy.github.io'`, `base: '/crowdy-blog'`.
- `.github/workflows/deploy.yml`:
  - Triggers on push to `main` and manual dispatch.
  - Steps: checkout → setup-node → `npm ci` → `npm run sync` → `npm run build` → `actions/upload-pages-artifact` → `actions/deploy-pages`.
  - Uses `withastro/action` if it simplifies the above.
- GitHub repo Settings → Pages → Source: GitHub Actions.

**Note on sync in CI:** Because `~/dev/crowdy/blog/` is local-only, the sync output (`src/content/posts/`) is committed to the repo. The CI build does **not** re-run sync — it builds from the committed content. The `npm run sync` step is run locally before commit. (This avoids needing the source tree on the runner and keeps the deployed content reproducible from the repo.)

Operational flow:
```
local: edit markdown → npm run sync → git commit → git push
CI:    npm ci → npm run build → deploy
```
